What I am building: - A pipeline that extracts textbook content from the deployed Docusaurus site or local build output - Chunks the content deterministically - Generates embeddings using Cohere - Stores vectors in Qdrant with strict metadata Audience: - Backend / AI engineers maintaining the RAG system Success criteria: - 100% textbook pages are embedded - Re-running the pipeline produces no duplicate vectors (idempotent) - Each vector includes metadata: doc_id, section_title, url, source_type - Qdrant collection is versioned Constraints: - Embeddings: Cohere only - Vector DB: Qdrant - Chunk size and overlap must be explicitly defined - No hardcoded content - No LLM usage beyond embeddings Not building: - Retrieval logic - Any chatbot or API - Frontend integration"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Automated Content Ingestion (Priority: P1)

As a backend engineer, I want to run a single, deterministic command that crawls the textbook content, chunks it, generates embeddings, and stores them in a versioned Qdrant collection, so that the RAG system has a reliable and up-to-date knowledge base.

**Why this priority**: This is the foundational process for the entire RAG system. Without accurate and complete content ingestion, no other part of the system can function.

**Independent Test**: The pipeline can be executed against a local build of the Docusaurus textbook. The resulting Qdrant collection can then be queried to verify that content is present, correctly structured, and includes all the required metadata.

**Acceptance Scenarios**:

1.  **Given** a clean Qdrant instance and a local Docusaurus build output, **When** the ingestion script is executed, **Then** a new, versioned collection is created in Qdrant containing vectors for 100% of the textbook pages.
2.  **Given** an existing, versioned Qdrant collection, **When** the ingestion script is executed again on the same source content, **Then** the process completes without creating duplicate vectors or collections, confirming idempotency.

## Requirements *(mandatory)*

### Functional Requirements

-   **FR-001**: The system MUST provide a reproducible script or CLI command to execute the entire ingestion pipeline.
-   **FR-002**: The pipeline MUST be able to extract content from either a deployed Docusaurus website URL or a local build output directory.
-   **FR-003**: The pipeline MUST chunk the extracted Markdown content deterministically.
-   **FR-004**: The system MUST use the Cohere API to generate embeddings for each content chunk.
-   **FR-005**: The system MUST store the generated embedding vectors and their associated metadata in a Qdrant collection.
-   **FR-006**: Each vector's metadata MUST include `doc_id` (a unique identifier for the source page), `section_title`, `url` (a direct link to the content), and `source_type` (e.g., 'text', 'code').
-   **FR-007**: The Qdrant collection created by the pipeline MUST be versioned to allow for updates and rollbacks.
-   **FR-008**: The pipeline MUST NOT utilize any Large Language Models (LLMs) for tasks other than generating embeddings.
-   **FR-009**: The content chunking strategy MUST be explicitly defined as: Chunk Size: 512 tokens, Chunk Overlap: 50 tokens. These values MUST be configurable.

### Key Entities

-   **Content Chunk**: A segment of text or a code block extracted from a textbook page. It is the base unit for embedding.
-   **Embedding Vector**: The numerical representation of a `Content Chunk` generated by Cohere, stored in Qdrant. Associated with it is a metadata payload.

## Success Criteria *(mandatory)*

### Measurable Outcomes

-   **SC-001**: Coverage: 100% of the Docusaurus textbook pages are processed and have corresponding vectors in the Qdrant collection.
-   **SC-002**: Idempotency: Re-running the ingestion pipeline on identical source content results in an identical Qdrant collection, with no new or duplicate vectors created.
-   **SC-003**: Data Integrity: 100% of vectors in the Qdrant collection have the complete, required metadata payload (`doc_id`, `section_title`, `url`, `source_type`).
-   **SC-004**: Reproducibility: The entire process can be successfully executed via a single, documented CLI command.
